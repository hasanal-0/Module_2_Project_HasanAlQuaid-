## Project Overview

Merge sort, quicksort, and heapsort all have an average time complexity of O(n log n), so on paper they should be about equally efficient. This project tests whether that holds up in practice by timing pure-Python implementations of all three algorithms and comparing their runtimes with statistical tests.

The main question is: **Among three O(n log n) sorting algorithms implemented in pure Python (merge sort, quicksort, and heapsort), does the choice of algorithm affect runtime when sorting random arrays of 10,000 integers?**

- **H₀:** The mean runtime is the same for all three algorithms.
- **H₁:** At least one algorithm's mean runtime differs from the others.

## Data Description

All data in this project was **generated by my own experiment**, so there is nothing to download. Each run sorts a newly generated random array of 10,000 integers (values 0 to 1,000,000) and records how long the sort took in milliseconds.

### Data — `data/`

- **`raw/`** — Runtimes recorded directly by the experiment scripts:
  - `pilot_runtimes.csv` — pilot study (20 runs per algorithm)
  - `runtimes.csv` — main experiment (53 runs per algorithm)

- **`processed/`** — Cleaned data used for the statistical analysis:
  - `runtimes_clean.csv` — main experiment data with an `is_outlier` flag and a `log_runtime` column added

### Python scripts — `src/`

- **`sorting_algorithms.py`** — Merge sort, quicksort, and heapsort, plus a correctness check against Python's built-in `sorted()` on 206 test lists
- **`pilot.py`** — Pilot study: times each algorithm on 20 random arrays
- **`power_analysis.py`** — Calculates η² and Cohen's f from the pilot, then the required sample size (planned for a medium effect: 53 runs per algorithm)
- **`experiment.py`** — Main experiment: times each algorithm on 53 random arrays in a shuffled order
- **`clean_data.py`** — Checks the data, flags outliers with the IQR rule (kept, not removed), and adds a log-transformed runtime column
- **`statistical_analysis.py`** — Assumption checks, one-way ANOVA, η², Kruskal-Wallis check, Tukey's HSD, and figures

### Reports — `reports/`

- **`descriptive_stats.csv`** — n, mean, median, SD, IQR, and skewness for each algorithm
- **`posthoc_results.csv`** — Tukey's HSD results as runtime ratios with 95% confidence intervals and adjusted p-values
- **`figures/`** — Histograms and Q-Q plots (raw and log runtimes), the Tukey confidence interval chart, and the runtime box plot

## Usage

Run every script **from the repository's main folder** (not from inside `src/`), in this order:

1. `sorting_algorithms.py`
    ```
    py -3.11 src/sorting_algorithms.py
    Outputs: none (prints whether all three algorithms sorted every test list correctly)
    ```
2. `pilot.py`
    ```
    py -3.11 src/pilot.py
    Outputs: data/raw/pilot_runtimes.csv
    ```
3. `power_analysis.py`
    ```
    py -3.11 src/power_analysis.py
    Outputs: none (prints η², Cohen's f, and the number of runs needed)
    ```
4. `experiment.py`
    ```
    py -3.11 src/experiment.py
    Outputs: data/raw/runtimes.csv
    ```
5. `clean_data.py`
    ```
    py -3.11 src/clean_data.py
    Outputs: data/processed/runtimes_clean.csv
    ```
6. `statistical_analysis.py`
    ```
    py -3.11 src/statistical_analysis.py
    Outputs: reports/descriptive_stats.csv, reports/posthoc_results.csv, reports/figures/*.png
    ```

**Before running steps 2 and 4,** close other applications and browser tabs and keep the laptop plugged in, since background activity adds noise to the timings.

To re-analyze the exact data from this project without re-running the experiment, skip steps 2–5 and run only `statistical_analysis.py`. It reads the `runtimes_clean.csv` already in this repo.

## Results

- **One-way ANOVA** (log runtimes): F(2, 156) = 101.12, p < 0.001 → reject H₀
- **Kruskal-Wallis** check: H = 102.92, p < 0.001 → same conclusion
- **Effect size:** η² = 0.56 (large)
- **Tukey's HSD:** all three pairs differ significantly
  - Quicksort took about **0.54×** as long as heapsort
  - Quicksort took about **0.62×** as long as merge sort
  - Merge sort took about **0.86×** as long as heapsort

**Ranking (fastest to slowest): quicksort, merge sort, heapsort.**
